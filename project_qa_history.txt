Q4: "Now we need to add a test reporting tool to save test logs, results, and screenshots. Which platform do you recommend?"

A4:
We highly recommend the built-in **Playwright HTML Reporter** because it is zero-setup, dependency-free, and natively integrates with screenshots and execution trace recordings. Q5: "there is an API for this website? if so: lat's add some API test for this website"
------------------------------------------------------------------------
A5:
Yes! By intercepting real network traffic on Sport5 using Playwright's Page event listener, we discovered their active backend API endpoints. One of the main dynamic endpoints they use is `https://www.sport5.co.il/Ajax/GetNewsRoomTS.aspx` (which returns active news room epoch timestamps).

We added an API integration spec (`src/tests/sport5Api.spec.ts`) that runs directly in milliseconds without launching full GUI browsers, ensuring:
1. Dynamic backend endpoint `GetNewsRoomTS.aspx` returns status 200 OK and a valid dynamic timestamp response.
2. Main Homepage API responds with healthy status and the correct `text/html` headers.

Q6: "add non native mobile tests using chrome"
------------------------------------------------------------------------
A6:
We added non-native (responsive) mobile web testing by configuring Playwright device emulation in `playwright.config.ts`. We set up separate projects for "Desktop Chrome" and "Mobile Chrome" (using the emulated `Pixel 5` preset). 

When run on Mobile Chrome, Sport5 automatically redirects to their dedicated mobile subdomain (`https://m.sport5.co.il/`). 

We created a mobile test suite (`src/tests/sport5Mobile.spec.ts`) verifying:
1. Auto-redirection to the `m.sport5.co.il` subdomain.
2. The viewport and layout scale properly for screens under 500px.
3. Mobile layout components (like specific category links) are attached and interactable in the mobile DOM.
4. Auto-saves mobile screenshots to `screenshots/sport5-mobile-homepage.png`.
